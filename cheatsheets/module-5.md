# Module 5 on one page: Claude Code & the Agent SDK

CCDV-F · four areas of the exam: Claude Code Operation (3.1%), Configuration Management (4.1%), Claude Hooks (1.0%) and Agentic Customization (4.1%), about 6 or 7 of 53 items, plus parts of Software Engineering Foundations, Agent Construction and Claude Application Design · checked against the Claude Code docs, the Claude docs and the Claude Help Center on 2026-10-09 and 2026-10-10

| Lesson | Keep this |
|---|---|
| 5.1 Operating Claude Code | Explore, plan, code, commit. Plan when the change touches several files or unfamiliar code; skip the plan when you could describe the diff in one sentence. Choose the permission mode by the risk: plan mode explores without editing; manual approval asks before each edit and command; accept edits lets edits through; auto mode reduces prompts but does not guarantee safety; don't ask is for CI and scripts. Deny rules block in every mode. Checkpoints (Esc twice, rewind) undo inside a session but not files changed by Bash; git is the record. `/context`, `/compact` with a focus, `/clear` between unrelated tasks, `/rename` and `/resume`. |
| 5.2 Durable project context | `/init` writes or improves CLAUDE.md; keep it lean (under 200 lines; ask of every line: would Claude get it wrong without it?). CLAUDE.md is context, not enforced configuration, delivered as a user message after the system prompt. `.claude/rules/*.md` with a `paths` field load only when Claude touches matching files. `CLAUDE.local.md` is personal. Auto memory is Claude's own notes, on your machine. Settings are configuration: managed > local > project > user for the same key (the highest level that sets it wins); list keys like `allow` merge. |
| 5.3 Skills, commands and subagents | A skill (`SKILL.md`: description, `allowed-tools`, body, supporting files) loads its body only when used; only the description sits in context. Custom commands are skills; `disable-model-invocation: true` means only you start it. A subagent (`.claude/agents/*.md`: tools, model, memory, skills) works in its own context and returns a summary. Pin a full model ID; an alias moves. With `memory` on, a subagent can write its memory folder even with read-only tools. |
| 5.4 Hooks | A hook runs every time; an instruction is a request. PreToolUse can block (exit 2, the reason on stderr) before the call runs; PostToolUse can't undo; Stop with exit 2 keeps Claude working (check `stop_hook_active`). A matcher of `Edit|Write` never sees Bash. Hooks for a guard, a formatter, a test gate; test the hook scripts themselves. |
| 5.5 Plugins | A plugin packages skills, commands, agents, hooks and MCP servers (`.claude-plugin/plugin.json`; everything else at the plugin root; `${CLAUDE_PLUGIN_ROOT}` in paths). It runs as you. Declare dependencies with a version range, tag releases (`claude plugin tag`), validate (`claude plugin validate`). For a team: `extraKnownMarketplaces` and `enabledPlugins` in the repository's `.claude/settings.json` (enable each dependency too). |
| 5.6 Claude Code in the pipeline | `claude -p` with `--output-format json` (or `stream-json`), `--json-schema` for a typed verdict in `structured_output`; check the result's `subtype` first. In CI: `--permission-mode dontAsk` with only the tools the job needs, a turn limit, a budget, `--no-session-persistence`, the key in a secret, and an exit code that fails the build. `--bare` skips hooks, skills, plugins, MCP servers, memory and CLAUDE.md. A model's review is advice; a person still merges. |
| 5.7 The Claude Agent SDK | Claude Code's harness as a library: `query()` streams messages to a `ResultMessage` (result, usage, cost, session ID, subtype). `ClaudeAgentOptions`: `allowed_tools` pre-approves, `disallowed_tools` removes, `dontAsk` denies the rest; hooks are Python functions; `output_format` for structured output; `max_turns` and a budget. `setting_sources=["project"]`, `plugins` and `skills` reuse the same skill as Claude Code. The default system prompt is minimal, unlike `claude -p`. Sessions resume by ID. |
| 5.8 One app, many interfaces | claude.ai adds Anthropic's system prompt, your instructions, a project's knowledge and memory; Claude Code adds its own prompt and CLAUDE.md (Desktop reads the same files); `claude -p` the same unless `--bare`; the SDK starts minimal; the Messages API gets only what you send and is stateless. Walls: one session per user or item, resumed only by its own ID; fresh by default; a lesson file is data, never the system prompt. One task per session; start fresh after two failed corrections. |

## The four traps

| Trap | It sounds like | Why it's wrong |
|---|---|---|
| Put it in CLAUDE.md | "Write it at the top of CLAUDE.md, in capitals." "Add 'use version 2' to CLAUDE.md." | CLAUDE.md is context, not enforced configuration: Claude usually follows it, and a hurried request can talk it out of it. A rule that must hold goes where it's enforced: a deny rule in settings, a PreToolUse hook that exits with code 2, a version range in the plugin's manifest. |
| Turn off the brakes | "Run it with --dangerously-skip-permissions." "Use auto mode for the risky change." "Grep the output for 'fail'." | Faster, until a run edits the file it shouldn't or the check misreads free text. Pick the mode by the risk; in a pipeline use dontAsk with only the tools the job needs, a schema for the result, and an exit code that fails the build. Deny rules hold in every mode. |
| Keep it all in one context | "Put the whole checklist in CLAUDE.md." "Keep one long session for every customer." "Compact between customers." | Every line goes to the model on every request, adherence drops as the file grows, and one user's data can reach another's. Keep CLAUDE.md lean, scope rules by path, let a skill load when it's used, give heavy reading to a subagent, start a fresh session per task and per user. |
| Build it yourself | "Write your own tool loop and file tools." "Scrape the terminal." "Copy the other plugin's MCP server into yours." | You rebuild what Claude Code already ships and maintain it alone. Use `claude -p` for scripts and CI, the Agent SDK for your own service (its tools, its permissions, your skills), and share a setup as a plugin with its dependencies declared. |
