# Module 3 on one page: Tools & the Claude API in Depth

CCDV-F · two skills of the exam: Tool Implementation (Domain 8, 4.4%) and Claude API Mechanics (Domain 2, 6.8%), about 6 of 53 items (API mechanics also reaches into other modules) · checked against the Claude docs on 2026-10-09

| Lesson | Keep this |
|---|---|
| 3.1 Tool use from first principles | A tool is a name, a description and an `input_schema`. The description says what the tool does, when to use it and when not, what each input means and what it doesn't return (three to four sentences or more). Claude asks; your code acts: `stop_reason: "tool_use"` → run each `tool_use` block → send `tool_result` blocks (matched by `tool_use_id`) → repeat until `end_turn`, with a turn limit. A dispatch table maps tool names to your functions; tools that reach outside get your own timeouts and headers. |
| 3.2 Multi-turn and parallel tools | Several `tool_use` blocks in one reply: run them (independent reads can run at once) and send every `tool_result` back together, in one user message, results before any text. A failure goes back as `is_error: true` with what went wrong and what to try next, never as an empty string. Within a tool-use turn, pass the thinking blocks back unchanged, with their signatures. |
| 3.3 Tool Runner and server tools | The SDK Tool Runner runs the loop for you (and turns an exception into an `is_error` result). Use a manual loop where a person must approve a call. Server tools (web search, web fetch, code execution) run on Anthropic's platform: no `tool_result` from you; web fetch loads only URLs already in the conversation; web search costs $10 per 1,000 searches plus tokens. Keep the 3–5 most used tools loaded and defer the rest with tool search when there are 10 or more. |
| 3.4 Images, PDFs, citations and files | Images in `image` blocks, PDFs and text in `document` blocks, before the question. An image costs (width / 28) × (height / 28) tokens, after scaling to the model's limit; each PDF page is read as text and as an image. Citations on a document give each claim its exact `cited_text` and where it is; they can't be combined with structured outputs. The Files API: upload once, send the `file_id`; files are shared by the whole workspace, and their content is still billed as input tokens. |
| 3.5 Realtime vs batch | Someone waiting: the Messages API. Volume that can wait: the Message Batches API, 50% off every token, most batches done within an hour, at most 24 hours; up to 100,000 requests or 256 MB; results kept 29 days. Each request has a `custom_id` (1–64 letters, digits, `-`, `_`); results come back in any order, so match by `custom_id`. Errored, canceled and expired requests aren't billed. List endpoints return a page at a time; the SDK's list methods follow the pages as you loop. |

## The four traps

| Trap | It sounds like | Why it's wrong |
|---|---|---|
| Faster means cheaper | "Send the requests in parallel threads to cut the cost." "Stream it, it's cheaper." | Parallel and streamed calls change when the answer arrives, not the price per token. For work nobody waits on, the Message Batches API halves the price. |
| Built-in reaches anything | "Give Claude web fetch so it can read our intranet." "Make the refund tool a server tool." | Server tools run on Anthropic's platform under its own rules: the public web, URLs already in the conversation, a sandbox. Your database, network and payments need client tools your code runs, with your credentials, timeouts and approval steps. |
| Just tell it | "Tell Claude to always ask before a refund." "Ask for exact quotes with page numbers." "Only send valid ids." | A sentence in the prompt is a request, not a guarantee. Use a manual loop where a person approves, citations that point into the document, and a description and schema that say exactly what the input is. |
| Drop the thread | "One user message per tool result." "Return an empty string when a tool fails." "Raise an exception and the runner waits." "Pair batch results by position." | The loop has a contract: all results in one user message, failures as `is_error` with what happened, thinking blocks passed back, batch results matched by `custom_id`. |
