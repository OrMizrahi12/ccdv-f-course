# Module 7 on one page: Production engineering, evals & cost

| Lesson | Keep this |
|---|---|
| 7.1 Errors that will happen | Classify first. Retriable (429 with `retry-after`, 5xx, 529, timeouts): wait, back off with jitter, retry. Terminal (400, 401, 403, 404, 413): stop, or fix the request. A 429 can be a tier spend cap (`enforced_spend_limit_reached`, no `retry-after`): stop and alert. A 200 with `stop_reason: "refusal"` isn't an error, and it isn't an answer: fall back. The SDK retries twice by default and honors `retry-after`; your code sets `max_retries` and a timeout per feature. Retries multiply load: cap the requests in flight. |
| 7.2 Tracing and debugging | Log the `request-id` of every call. One job, one trace: `generate`, the model call (`chat <model>`: usage, stop reason), the HTTP request (status, request id, one span per retry), then `validate`. OpenTelemetry's GenAI conventions name the attributes (still in Development). A red HTTP span is the integration layer; a green HTTP span with a red `validate` is the model output. Log ids, usage, versions and decisions, not bodies, keys or personal data. |
| 7.3 Evals | Criteria first, measurable. A dataset of real and edge cases, each labeled with a reason; tune on dev, prove once on held-out. Grade with code first, a rubric judge for judgment, people for the labels. Calibrate the judge: agreement, kappa, and the error that costs most (a false pass). A bigger judge isn't proof; the numbers are. |
| 7.4 Testing layers | Unit and contract tests touch nothing; integration tests cross one real boundary, on purpose; end-to-end runs the app; evals call the real model and score a distribution against thresholds; load tests go before a launch. Gate releases on evals in CI, with a spend cap; capability evals that pass reliably graduate to regression. Throughput flattens at the limit while latency and 429s climb. |
| 7.5 Prompt caching in depth | The prefix is `tools`, then `system`, then `messages`. Stable content first, the changing part after the mark. Below the minimum (4,096 tokens on Claude Haiku 4.5), nothing is cached and nothing complains. A timestamp in the prefix, a tool change, another model or thinking setting breaks it. Check `cache_read_input_tokens`; cache diagnostics names where the prefix changed. Reads cost a tenth of input; writes 1.25x (2x for the 1-hour TTL). |
| 7.6 Staying within budget | Three budgets per feature: cost per completed task (failed attempts and repairs count), p95 latency, completion rate. Route by measurement: the cheapest model and effort that meets the quality line. Several agents share one ledger that reserves each request's worst case before it's sent. Backstops, soft to hard: a task budget, `max_tokens`, the ledger, an SDK session budget, the workspace spend limit. Sample production output for the calibrated judge. |

## The four traps

| Trap | It sounds like | Why it's wrong |
|---|---|---|
| Retry everything | "Retry every failed request ten times." "Raise max retries until it works." | A spend cap, a bad request, bad credentials or a refusal won't succeed if you send it again, and retries multiply the load. Classify first: wait and retry the transient, stop and alert on the rest, fix the request, or fall back. |
| Eyeball a few outputs | "Read three examples after each prompt change." "Use the biggest model as the judge." "Let the writer grade itself." | None of it is measured. Write criteria as numbers, label a set with reasons, grade with code first, and calibrate the judge against the labels. |
| It's green, so it's fine | "Every call returned 200." "Caching is switched on." | A 200 can carry a refusal, a reply cut off at `max_tokens`, or the wrong content; a cache can be silently off. Trace to the failing layer, read the `stop_reason`, and check the cache fields. |
| Spend your way out | "Move everything to the largest model." "Raise the limit." "Batch everything for the discount." | Cost goes up and quality is still unproven; batch suits only work that can wait. Set a budget per feature, measure, and route each to the cheapest setup that meets its quality line, with one ledger and backstops. |
