# Module 6 on one page: MCP & agentic customization

| Lesson | Keep this |
|---|---|
| 6.1 MCP from zero | A host (Claude Code, Claude Desktop, your app) runs one client per server. Who controls each building block: tools, the model (each call can be approved or denied); resources, the application or the person (`@` attaches one, no tool call); prompts, the user (a `/` command). MCP makes a capability reusable: build it once, and every host that speaks MCP can use it. A deny rule (`mcp__server__tool` in `permissions.deny`) blocks a tool; a sentence in the description doesn't. |
| 6.2 A Python server | `MCPServer` from the MCP Python SDK (v2; older tutorials call it `FastMCP`): `@mcp.resource("lesson://{id}")`, `@mcp.tool` with type hints for the schema and read-only annotations, `@mcp.prompt`. Raise `ToolError` for a bad input: the client gets `isError: true` and your message; an unexpected exception's text never leaves the server. Over stdio, stdout is the wire: never print. Test in memory; inspect with the MCP Inspector; connect with `claude mcp add --transport stdio`, or from an API app with your own MCP client and the SDK's client-side helpers. |
| 6.3 Transports and scopes | stdio for one local host; Streamable HTTP for many. Validate `Origin`, bind to localhost when local. The 2026-07-28 revision removed protocol-level sessions (`server/discover`, each request carries its version); 2025-11-25 used an `initialize` handshake and a session id. Client features: sampling, roots, elicitation (the server asks the person), notifications. Claude Code scopes: local (you, this project), project (`.mcp.json`, shared, approved on first use), user (you, every project); the same name in two scopes warns of a conflict. The API's MCP connector calls a public remote server during the request; it can't reach `localhost` or a stdio server. |
| 6.4 The right tool | Ask in this order: Anthropic ships it and where it runs doesn't matter → a built-in tool. What's missing is knowledge or a procedure → a Skill. Several hosts need it, or it needs its own process, credentials or rights → MCP. One app needs your code in its own loop → a custom tool. Weigh reuse, maintenance, context cost and control. Measured once on Haiku 4.5: custom tool +767 tokens, three MCP tools +878, web fetch +1021, a Skill's description +44 (+440 when used). Write the choice down with what you give up. |
| 6.5 Enterprise systems | An HTTP MCP server is an OAuth resource server: check every token's audience and scopes; 401 with the metadata address when there's none. Never pass a token through to another service. Keep secrets out of the repo and config: `headersHelper` fetches the header when Claude Code connects, so rotating needs no edit; workload identity federation means no static keys. Keep private systems private: a client inside the network, the client-side helpers in your own app, or an outbound-only tunnel; never an open inbound port. Scope a security review first: data, identities, network path, least privilege, change control. |

## The four traps

| Trap | It sounds like | Why it's wrong |
|---|---|---|
| Paste the data in | "Put the whole clause library in the system prompt." "Send the nightly export with every request." | It costs tokens on every call, goes stale, and moves the data outside its access controls. Let the person attach a resource, let a tool fetch only what's needed when it's needed, and let a Skill load when it's used. |
| Hard-code it in the prompt | "Tell Claude in the tool description to wait for the person." "Mark it read-only and it's safe." "Paste the token into the config." | A sentence is a request, an annotation is a hint, and a stored secret leaks. Use the control that holds: a resource or prompt the person picks, permission rules, a `headersHelper`, short-lived tokens whose audience the server checks. |
| Open it up to make it work | "Give the server a public address so the connector reaches it." "Forward the user's token." "Turn the check off for now." | Every inbound door is a new attack surface, and a forwarded token works where it shouldn't. Keep the server private and bring the client to it; check every token, pass none on. |
| Build the biggest thing | "An MCP server for one app's web fetch." "Keep sessions in memory behind the load balancer." "A new transport to fix a print statement." | You build, secure and maintain more than the need. Size up from the constraint: built-in, custom tool, Skill, then MCP when several hosts need it. Keep servers stateless, and fix the bug where it is. |
